# Sudoku AI 要件定義書 (Requirements Specification)

## 1. プロジェクト概要

### 1.1 システムの目的
「Sudoku AI (スマート数独アシスタント)」は、プレイヤーの論理的思考力を育てることを目的とした、次世代の数独（ナンプレ）Webアプリケーションである。
単に答えを教えるだけのツールではなく、「なぜその数字が決まるのか」「盤面のどの着眼点に注目すべきか」を段階的にアドバイスする機能を備え、初心者から上級者までが快適に数独を学び、楽しめる環境を提供する。

### 1.2 背景と課題解決
- **従来の数独アプリの課題**:
  - 解き方が分からないときに「正解の数字」が一括で埋まってしまい、プレイヤーの思考や学習に繋がらない。
  - ランダム削除によって生成された問題に複数解（別解）が存在し、論理的に正しい手を打ってもミス判定される理不尽が生じる。
  - 誤入力がある状態でヒントを求めると、誤った数字を前提にした破綻した候補が正解として案内されてしまう。
- **本システムのアプローチ**:
  - **100% 唯一解保証**: MRV（最小候補数優先）バックトラッキング探索による解数検証を行い、厳密に唯一解が保証されたパズルのみを生成。
  - **誤入力優先検知・修正ガイダンス**: 誤入力がある盤面では、他のマスを案内する前に誤入力の修正を最優先で案内。
  - **段階的AIコーチング**: Gemini API とローカル推論エンジンを連携させ、ノーヒントから着眼点・マス特定・完全解説まで4段階でヒントを提供。
  - **BYOK (Bring Your Own Key)**: 利用者が自身の Gemini API キーを安全に利用でき、サーバーレス環境でも制限なく利用可能。
  - **盤面画像取り込み**: 新聞・雑誌の数独を撮影した写真や、端末に保存済みの画像を Gemini の画像認識で読み取り、アプリ上でプレイ・ヒント利用を可能にする。

## 2. システム機能要件 (Functional Requirements)

### 2.1 ゲームプレイ & 盤面操作機能
- **FR-1.1 9x9 数独盤面の表示・操作**
  - 標準的な 9x9 グリッド（3x3 ブロック × 9）を表示する。
  - マウス/タップ操作、および矢印キーによるマス選択に対応する。
  - 選択中のマス、同行、同列、同3x3ブロックのハイライト表示（関連セル強調）。
  - 同一数字が入力されているマスのハイライト表示。
- **FR-1.2 数字入力 & ナンパッド**
  - ナンパッド（1〜9）およびキーボード（1〜9キー）からの数字入力に対応する。
  - 初期配置（問題の手がかりマス）はロックされ、編集・消去できない。
  - ナンパッド各ボタンの下部に、その数字の「盤面への残り配置可能個数」をリアルタイム表示する（配置完了時は完了スタイルへ変化）。
- **FR-1.3 メモ機能 (Pencil Notes)**
  - 「メモモード」への切り替え（ボタンまたは `N` キー）。
  - マスごとに 1〜9 の候補数字をミニグリッド（3x3）で表示・トグル入力。
  - あるマスに確定数字が入力された場合、同行・同列・同ブロックのピアセルから該当数字のメモを自動除去（クリーンアップ）。
  - 「全メモ自動入力」機能により、現盤面でルール上配置可能な全候補を一括計算・反映。
- **FR-1.4 アクションツール**
  - **元に戻す (Undo)**: 直前の操作（数字入力、メモ入力、消去）を履歴上限（30手）まで取り消す。
  - **消去 (Erase)**: 選択中のマスの入力数字またはメモを消去（Backspace / Delete キー対応）。
  - **誤入力リセット (Check)**: 盤面内の誤入力マス（正解と異なる入力数字）を一括消去（空マスに復元）し、ミス回数を 1 カウントする。誤入力が 0 件の場合はミス回数を消費せず「診断正常」を通知する。
  - **AI自動解答 (Solve All)**: パズルの完成盤面を一括展開。
- **FR-1.5 ミス制限 & ゲームオーバー**
  - 通常の数字入力時は正誤にかかわらず同一カラー（即時赤文字化なし）で表示し、即時ミスカウントは行わない（総当たりチート防止・思考保護）。
  - 「誤入力リセット」アクションにより誤入力がクリアされた場合のみ、ミス回数が 1 カウントされる（最大 3 回まで許容）。
  - ミス回数が上限（3回）に達した場合はゲームオーバーとなり、新規ゲームへのリスタートを促す。
- **FR-1.6 タイマー機能 & 一時停止・再開**
  - ゲーム開始（または盤面生成・ロード）からの経過時間を `MM:SS` 形式で計測・表示。
  - **一時停止 / 再開**:
    - ヘッダーのタイマー脇に「一時停止 / 再開」ボタン（⏸️ / ▶️）を配置。
    - 一時停止中はタイマーのカウントアップを停止。
    - **アンチチート（不可視化）**: 一時停止中は盤面グリッド全体にすりガラス状のオーバーレイ（`backdrop-blur-md`）を表示し、マスの数字・メモ・ハイライトを完全不可視化する。オーバーレイ中央に「再開する」ボタンを配置。
    - 一時停止中はナンパッド、アクションツール、ヒント、キーボード入力等のすべての盤面更新操作を無効化（`disabled`）する。
  - ゲームクリア時またはゲームオーバー時にタイマーを自動停止。

### 2.2 パズル生成 & 難易度管理機能
- **FR-2.1 5段階の難易度**
  - ユーザーの習熟度に合わせて以下の 5 段階から選択可能とする：
    1. **入門 (Beginner)**: 手がかり数 約42〜45マス（削除目標: 36〜39マス）。Naked Single（唯一候補）だけでサクサク解き進められる初心者向け。
    2. **初級 (Easy)**: 手がかり数 約36〜38マス（削除目標: 43〜45マス）。Naked Single に加えブロック内の Hidden Single を活用。
    3. **中級 (Medium)**: 手がかり数 約30〜32マス（削除目標: 49〜51マス）。行・列の Hidden Single や基本候補の消去法が必要。
    4. **上級 (Hard)**: 手がかり数 約25〜27マス（削除目標: 54〜56マス）。Naked Pair / Hidden Pair などの同盟ペア技法を駆使。
    5. **達人 (Expert)**: 手がかり数 約22〜24マス（削除目標: 57〜59マス）。多重な候補絞り込みと深い先読みが求められる高難度パズル。
- **FR-2.2 厳密な唯一解保証 (Unique Solution)**
  - 有効な完成盤面からマスをランダム順に1マスずつ仮削除し、解が厳密に1つ（`countSolutions === 1`）である場合のみ削除を確定する。
  - 解が2つ以上になる場合は直ちにマスを復元し、スキップする。
  - 全81マスの試行完了時点で目標削除数に達していない場合でも、唯一解を最優先とし、その安全な盤面を返却する。
- **FR-2.3 新規ゲーム生成**
  - 難易度バーから難易度（5段階）を選択して即座に新しいパズルを生成・開始可能。

### 2.3 ローカル論理ヒント機能 (Rule-based Hint)
- **FR-3.1 誤入力の最優先検知 (Correction Hint)**
  - 盤面に誤った数字（正解と異なる入力）が存在する場合、通常の次の一手探索を中断し、最優先で誤入力マスを指摘する。
  - **正解数字の非表示**: 該当マスに本来入る正解の数字は表示せず、入力された数字が誤りであることと消去・見直しを促す理由を表示する。
  - 対象マスを自動選択し、警告トーン（rose）でパネルに表示する。
- **FR-3.2 論理推論ヒント (Placement Hint)**
  - 誤入力がない場合、以下の推論戦略を順次スキャンして「次の一手」を提示する：
    1. **Naked Single (唯一候補マス)**: 同一行・列・ブロックの制約により、候補が1つに確定するマス。
    2. **Hidden Single (Block / Row / Col: 隠れ一択)**: そのブロック、行、または列内で、ある数字が入れるマスが1箇所しかないケース。
    3. **Advanced Deduction (高難度推論)**: 上記で見つからない場合のフォールバック（正解マスと数字を提示）。
  - おすすめのマスの座標（行・列）、正解の数字、確定する論理的理由を明示する。

### 2.4 Gemini AI アドバイザー機能
- **FR-4.1 4段階のヒントレベル**
  - ユーザーの習熟度や好みに合わせてヒントレベルを 1〜4 から選択可能：
    - **レベル1 (ノーヒント / 存在のみ)**: 具体的なマス・数字は言わず、着眼点の方向のみ（誤入力時は誤りの存在のみ）を促す。
    - **レベル2 (着眼点 / 範囲)**: 注目すべきブロックまたは行/列と使用できる解法パターン（誤入力時は誤りが存在する範囲）を伝える。
    - **レベル3 (マス特定)**: 注目すべき具体的なマス（行・列）を特定し、考える根拠を提示する（数字は伏せる）。
    - **レベル4 (直接回答 / 正解提示)**: 注目マスと正解の数字を明示し、解説を行う（誤入力時は保存された正解数字を提示し、架空の推論は捏造しない）。
- **FR-4.2 デュアル通信方式**
  - **Direct Client 方式 (推奨・本番環境)**: ユーザーが設定した API キーを用いて、ブラウザから Google Generative Language REST API (`gemini-2.5-flash`) へ直接リクエスト送信（Vercel 等のサーバーレス制限を受けない完全動作）。
  - **Server Proxy 方式 (開発環境)**: `.env` に設定されたデフォルトキーを用いて、Vite 開発サーバー経由（`POST /api/hint`）で通信。
- **FR-4.3 通信ライフサイクル & 中止制御**
  - ゲーム再開（新規ゲーム）時、または API キーの変更・削除時に、実行中のリクエストを即座に `abort()` し、表示状態を `idle` へリセットする。
  - 中止された古いリクエストの応答が後から画面に反映されることを完全に防止する。

### 2.5 勝利演出 & 盤面ロック
- **FR-5.1 クリア判定 & 演出**
  - 全マスが正解と一致した瞬間に勝利（クリア）と判定。
  - 紙吹雪アニメーション（`canvas-confetti`）を発火。
  - 勝利モーダル（クリアタイム、難易度、リスタートボタン）を表示。
  - 盤面を読み取り専用（ReadOnly）にロックし、以後のセル選択や編集を無効化。

### 2.6 設定 & ユーティリティ
- **FR-6.1 API キー設定モーダル (BYOK)**
  - ヘッダーの設定アイコン（⚙️）から Gemini API キーの入力・保存・削除が可能。
  - キーはブラウザの `localStorage` に暗号化/安全に保存され、ページをリロードすることなく即時反映される。
  - ヘッダー上に「Gemini AI (カスタムキー利用中 / デフォルトキー利用中)」の接続ステータスバッジを表示。
- **FR-6.2 テーマ切り替え**
  - ダークモードとライトモードのワンクリック切り替え（Tailwind `dark` クラス対応）。
- **FR-6.3 PWA & オフライン対応**
  - Service Worker (`vite-plugin-pwa`) による静的アセットのキャッシュ。
  - オフライン環境でもゲームプレイおよびローカル論理ヒントが100%利用可能。

### 2.7 盤面画像取り込み機能 (Image Import)

> [!NOTE]
> 本章は新規追加機能の要件である（ステータス：**設計確定・未実装**）。

- **FR-7.1 取り込み起動**
  - 難易度バーに「📷 画像から取り込み」ボタンを配置し、取り込みモーダルを開く。
  - 進行中のゲーム（入力済みマスが1つ以上ある状態）が存在する場合は、「この盤面で開始」押下時に現在のゲームが破棄されることを確認ダイアログで通知し、同意を得てから切り替える。取り込みを途中で中止した場合、現在のゲームはそのまま継続できる。
- **FR-7.2 画像の入力経路**
  - `<input type="file" accept="image/*">` を使用し、次のいずれの経路でも画像を選択できる：
    - **スマートフォン**: 写真ライブラリ（保存済み写真・スクリーンショット）からの選択、またはカメラ起動による撮影（OS 標準の選択メニューに委ねる）。
    - **PC**: ファイル選択ダイアログ、またはモーダル内へのドラッグ＆ドロップ。
  - 対応形式：JPEG / PNG / WebP（ブラウザが復号できる形式）。復号できない形式（例：PC版ブラウザでの HEIC）は、エラーメッセージで JPEG/PNG での再選択を促す。
  - 選択した画像はモーダル内にサムネイル表示し、読み取り前に確認・選び直しができる。
- **FR-7.3 画像の前処理（クライアント側）**
  - 送信前にブラウザ内で長辺を最大 1600px に縮小し、JPEG（品質 0.85）へ再エンコードする。
  - EXIF の回転情報を反映し、正しい向きで送信する。
  - 前処理後の画像サイズが 4 MB を超える場合はエラーとする。
- **FR-7.4 Gemini による盤面認識**
  - 前処理済み画像を Gemini（`gemini-2.5-flash`）へ送信し、9x9 の数字配列（空マスは 0）を **JSON 構造化出力** で取得する。
  - **印刷された初期数字（問題の手がかり）のみ**を抽出対象とし、手書きの書き込みやメモは抽出しないよう指示する。
  - 画像内に数独盤面が見つからない場合は「盤面なし」を返させ、エラーとして通知する。
  - 読み取りに自信がないマスを `uncertainCells` として返させ、プレビューで強調表示する。
  - 読み取り中はローディング表示とキャンセルボタンを表示する。キャンセルまたはモーダルを閉じた場合は通信を中止し、遅れて届いた結果は破棄する。
- **FR-7.5 プレビュー・手動修正**
  - 読み取り結果を 9x9 のプレビュー盤面として表示し、各マスをタップして 0〜9 に修正できる。
  - 次のマスを色分けして表示する：
    - 読み取りに自信がないマス（`uncertainCells`）
    - 同じ行・列・ブロックで数字が重複しているマス
  - 修正のたびに FR-7.6 の検証を再実行し、結果（手がかり数、解の状態）を即時に表示する。
- **FR-7.6 盤面の検証**
  - 次の順で検証し、すべて満たす場合のみ「この盤面で開始」ボタンを有効化する：
    1. 9x9 かつ各値が 0〜9 の整数であること。
    2. 行・列・ブロック内に数字の重複がないこと（`isBoardValid`）。
    3. 解が **厳密に1つ** であること（`countSolutions(board, 2) === 1`）。
  - 解が 0 個の場合は「解が存在しません。読み取り結果を確認してください」、2 個以上の場合は「解が複数あります。読み取り漏れの数字がないか確認してください」と表示する。
  - 手がかり数が 17 未満の場合は、唯一解にならない可能性が高い旨を補足表示する。
- **FR-7.7 取り込み盤面でのゲーム開始**
  - 検証済み盤面を初期盤面（ロックされた手がかり）とし、ソルバーで求めた解を正解データとして新規ゲームを開始する。
  - 開始後は通常ゲームと同一の機能（メモ、Undo、誤入力リセット、論理ヒント、Gemini コーチ、タイマー、勝利演出）がすべて利用できる。
  - 取り込み盤面には自動判定された難易度バッジ（例: 「取り込み (上級)」）を表示する。
- **FR-7.8 利用条件・エラー処理**
  - 本番環境では、ユーザーが Gemini API キーを設定済みであることを必須とする。未設定時はボタン押下時に API キー設定への導線を表示する（開発環境ではサーバープロキシ経由のデフォルトキーで動作可）。
  - オフライン時は読み取りボタンを無効化し、オンライン接続が必要である旨を表示する。
  - 通信エラー、認証エラー（キー不正）、利用上限超過、タイムアウト（60 秒）、応答形式不正の各ケースで、原因と対処が分かるメッセージを表示し、再試行できるようにする。
- **FR-7.9 取り込み盤面の難易度自動判定 (Difficulty Grading)**
  - 唯一解が確認された盤面（`initial`）に対し、ローカルの論理ソルバーをシミュレーション実行して「解くために必要な最高難度テクニック」と「手がかり数」から 5 段階難易度を自動判定する：
    - **入門 (Beginner)**: Naked Single（唯一候補）のみで最後まで解き切れる盤面。
    - **初級 (Easy)**: Naked Single + Hidden Single（ブロック内）で解き切れる盤面。
    - **中級 (Medium)**: 行・列の Hidden Single までを使って解き切れる盤面。
    - **上級 (Hard)**: Naked Pair / Hidden Pair などの同盟ペア候補除外技法が必要となる盤面。
    - **達人 (Expert)**: ペア技法でも確定せず、多重な連鎖・高度な候補除外や背理的推論が必要となる盤面。
  - 取り込みプレビュー画面およびゲーム画面上に「判定難易度: 上級 (同盟ペア)」のように根拠付きで表示する。外部通信を行わずローカルで瞬時（1ms未満）に判定する。

### 2.8 マイパズル保存・呼び出し機能 (Saved Puzzles)

- **FR-8.1 盤面の保存 (Save)**
  - ヘッダーまたはツールバーに「💾 保存」ボタンを配置。
  - 現在のゲーム状態（初期盤面、正解盤面、現在の入力盤面、メモ、経過秒数、ミス回数、難易度、出どころ）をブラウザの `localStorage` に保存。
  - 保存時に任意のタイトル（デフォルト: 「[難易度名] YYYY/MM/DD HH:mm」または「取り込みパズル YYYY/MM/DD」）を設定可能。
  - 最大 50 件まで保存可能とし、上限到達時は古いパズルまたは不要なパズルの削除を促す。
- **FR-8.2 保存済みパズルの呼び出し (Load)**
  - ヘッダーに「📁 マイパズル」ボタンを配置し、一覧モーダルを表示。
  - 保存されたパズル一覧（タイトル、難易度バッジ、保存日時、進捗率%、サムネイルグリッド）を表示。
  - 以下の操作が可能：
    - **「再開する」**: 保存時の途中経過（入力数字、メモ、経過タイム、ミス数）を復元してゲームを継続。
    - **「最初から解く」**: 初期盤面からタイマー・ミス数 0 でリスタート。
    - **「削除する」**: 確認の上、保存済みデータを削除。
- **FR-8.3 進行中ゲームとの調和**
  - 現在のゲームで未保存の操作がある状態でマイパズルをロードする場合、破棄の確認ダイアログを表示する。

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 性能要件 (Performance)
- **パズル生成速度**:
  - 入門・初級・中級: 平均 5 ms 未満
  - 上級: 平均 20 ms 未満
  - 達人: 平均 50 ms 未満（最大でも 200 ms 以内）
  - メインスレッドをフリーズさせず、画面のクリック応答性を阻害しないこと。
- **解探索処理**:
  - 1回の解カウント処理（`countSolutions`）は平均 0.1 ms 以内で完了すること。
- **難易度自動判定処理**:
  - 論理シミュレーションによる難易度採点は 1 回あたり 5 ms 以内で完了すること。
- **バンドルサイズ**:
  - Gzip 圧縮後の総転送サイズが 150 KB 未満であること（高速な初期表示）。
- **画像取り込み**:
  - 画像前処理（縮小・再エンコード）は 1 秒以内に完了すること（iPhone 13 Pro Max 相当）。
  - 盤面検証（`isBoardValid` + `countSolutions` + 難易度判定）はプレビュー修正のたびに実行するため、1 回 50 ms 以内で完了すること。
  - Gemini による読み取りは通常 15 秒以内を目標とし、60 秒でタイムアウトとする。
  - 画像処理用に新たな外部ライブラリを追加しない（Canvas / `createImageBitmap` 等のブラウザ標準 API で実装）。

## 4. スコープ外 (Out of Scope)

画像取り込み機能（FR-7）およびパズル管理（FR-8）の現行版では、以下を対象外とする。

| 項目 | 対象外とする理由・代替 |
|---|---|
| 紙面に手書きで書き込んだ途中経過（解答・メモ）の再現 | 印刷数字と手書き数字の判別精度を保証できないため。初期数字のみ取り込み、途中経過はアプリ上で入力し直す。 |
| 1 枚の画像に含まれる複数盤面の選択 | 先頭（最も大きく写っている）1 盤面のみを対象とする。必要に応じてトリミングした画像を選択してもらう。 |
| カメラ映像のリアルタイム枠検出・自動撮影 | OS 標準のカメラ・写真選択に委ねる。 |
| オフラインでの画像認識 | 端末内 OCR モデルの追加はバンドルサイズ要件に反するため。 |
| クラウド同期 / 複数端末間のパズル同期 | サーバーレス・BYOK アーキテクチャを維持するため。ローカルストレージ内で完結。 |
| 6x6、16x16、変形数独 | 標準 9x9 のみ対象。 |
